# YOLO 기준 성능 측정 결과 (비전)

이슈 #27. 현재 매장 인원 탐지 모델의 기준 성능을 정답 라벨로 측정한 결과다.
모델 정의서와 최종 발표의 근거 수치로 사용한다. 수치는 모두 실측이다.

카메라 명칭: **066_외부**(입구·대기), **067_1층**(좌석·주문), **068_2층_2**(유리 너머),
**071_2층_1**(좌석·통로).

## 1. 평가 설정

| 항목 | 값 |
|---|---|
| 모델 | YOLO11s (COCO 사전학습, 추가 학습 없음) |
| 대상 클래스 | person (class 0) |
| confidence | 0.30 |
| NMS IoU | 0.5 |
| 후처리 | agnostic NMS (한 사람 중복 박스 병합) |
| 입력 해상도 | 1920×1080 (원본) |
| 검증 데이터 | AI Hub 실내외 군중 특성 데이터 — 카페노아 4개 각도 |
| 프레임 범위 | 각 카메라 전체 프레임 (066_외부·067_1층 662장, 068_2층_2 636장, 071_2층_1 660장) |

ROI(구역) 설정은 인원수 정확도 측정에는 사용하지 않는다. 인원수는 화면 전체
탐지 수를 정답 counting과 비교한다. ROI는 구역별 집계·좌석 점유에만 쓰인다.

## 2. 평가 방법

정답 라벨의 bbox는 **머리 박스**다(평균 높이 56px, 가로세로비 1.08 = 정사각형).
YOLO가 내는 것은 **전신 박스**(가로세로비 2.18)라, 둘 사이 IoU가 거의 0이 되어
**표준 mAP50 / mAP50-95는 의미가 없다**(정탐지도 IoU 미달로 오탐 처리됨).

따라서 다음 지표로 측정한다.

- **인원수 MAE / 정확도**: YOLO 탐지 수 vs 정답 counting. 정확도 = 1 − MAE/정답평균.
- **Precision / Recall / F1**: 정답 머리 좌표가 예측 박스 안에 들어가는지로 매칭
  (headpoint-in-box). 머리 라벨 데이터의 표준 평가 방식이다.
  - TP: 정답 머리점이 어떤 예측 박스 안에 있음 (박스 1개당 1명)
  - FP: 정답 머리점이 없는 예측 박스 (오탐)
  - FN: 어떤 박스에도 안 잡힌 정답 머리점 (미탐지)
- **밀집도별 정확도**: 정답 collectiveness(High 50+/Mid 13~49/Low ≤12)별 MAE.

## 4. 밀집도별 정확도 (잘되는 / 어려운 상황)

| 카메라 | Low(≤12) MAE | Mid(13~49) MAE |
|---|---|---|

**공통 경향: 밀집할수록 정확도가 떨어진다.** 사람이 겹치면 뒤쪽 객체가 가려져
과소 계산된다. 한산한 실내(Low)에서는 MAE 1명 안팎으로 매우 정확하다.

## 5. 카메라별 해석 및 조치

- **071_2층_1 (최고)**: 인원수 정확도 87.9%, MAE 1.48로 가장 우수. 시야가 트여 있고
  밀집이 적당해 좌석·통로가 잘 잡힌다.
  → **조치: 현 설정 그대로 사용.**
- **067_1층 (균형 최고)**: Precision 94.0% / F1 87.6%로 오탐·미탐 균형이 가장 좋다.
  실내 정면 뷰라 안정적.
  → **조치: 현 설정 그대로 사용.**
- **066_외부**: Precision 85.0%로 가장 낮다. 대기 줄 밖 **행인·배경 인물**이 오탐(FP 1365)으로
  잡히기 때문.
  → **조치: 대기 구역 ROI로 구역 밖 인원 제외 (이미 적용, 동작 중).** 실사용 대기 인원은
  구역 안만 집계해 정확도를 높인다.
- **068_2층_2 (문제)**: Precision 95.9%로 높지만 **Recall 58.1%**로 최악. 탐지한 건 대부분
  맞지만 **사람의 42%를 아예 못 잡는다**. 원인은 밀집이 아니라(전 구간 Low인데도 MAE 3.80)
  **유리문 너머 촬영의 반사·왜곡**이다. 오탐이 아니라 **미탐지 문제**다.
  → **조치: 측정 가능하고 필요한 구역만 ROI로 지정해 인원 합산.** 유리 너머로 안 잡히는
  영역은 집계에서 제외한다. (카메라 재배치가 근본 해결이나 현 데이터로는 구역 한정으로 대응)

## 6. 성공 / 실패 사례 및 조치

**성공(잘 되는 상황)**: 실내 정면·자연스러운 각도, 한산~보통 밀집, 유리·장애물 없음
→ 067_1층·071_2층_1 Low 밀집에서 MAE ≈ 1.0. 현 설정 유지.

**실패(어려운 상황)와 조치**:

1. **유리/장애물 너머 촬영 → 미탐지 급증** (068_2층_2, Recall 58%)
   → 측정 가능한 구역만 ROI로 한정해 합산. 근본적으로는 카메라 위치 개선.
2. **밀집·겹침 → 뒤쪽 인물 과소 계산** (전 카메라 Mid MAE 2~3배)
   → 매장별 파인튜닝 필요(후순위, 전신 라벨 확보 조건 — 9절 참고).
3. **관심 구역 밖 인물 → 오탐** (066_외부 배경 인물)
   → 대기 구역 ROI로 구역 밖 제외 (이미 적용).

## 7. 재현 방법

동일 조건으로 다시 측정하려면:

```bash
# 로컬 데이터(AI Hub)와 ultralytics 환경이 있는 비전 담당 PC에서
py services/vision-worker/_local/evaluate_yolo.py            # 전체 프레임
py services/vision-worker/_local/evaluate_yolo.py --step 5   # 빠른 확인
```

- 스크립트: `services/vision-worker/_local/evaluate_yolo.py` (로컬 전용, 커밋 제외)
- 설정 고정: `conf=0.30`, `iou=0.5`, `agnostic_nms`, `class=person`
- 원본 이미지·라벨은 저장소에 없으므로 각자 AI Hub에서 받아야 한다.

## 10. 한계 및 추가 학습 판단

- 067_1층·071_2층_1·066_외부는 인원수 정확도 84~88%로 **현 모델 그대로 사용 가능**.
- 068_2층_2(60.5%)는 실사용 부적합하나, 원인이 **모델 성능이 아니라 카메라 위치(유리 너머)**다.
  → 구역 한정 ROI로 대응하고, 근본적으로는 카메라 재배치 과제로 분리한다.
- **이 데이터셋으로 파인튜닝하면 '머리 탐지 모델'이 된다**(정답이 머리박스). 그러면 발 위치
  기반 구역·좌석 판정이 깨지므로, **전신(full-body) 라벨 데이터를 확보한 뒤** 파인튜닝한다.
- 결론: **현 단계는 추가 학습 없이 YOLO11s 유지.** 파인튜닝은 전신 라벨 확보 후 후순위로 진행.
